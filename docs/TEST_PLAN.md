# Windows 실기기 테스트 계획

각 테스트는 운영자가 확인한 대상 시리얼, 물리 USB 위치, Windows 빌드, USB 드라이버 버전, Platform Tools 버전, 클라이언트 OS와 결과를 기록합니다. Windows 10과 Windows 11에서 아래 절차를 별도로 실행하고 원격 Windows, Ubuntu, macOS를 각각 연결합니다.

| 시험 | 절차와 합격 기준 |
| --- | --- |
| 기본 및 드라이버 | 일반 권한으로 서버의 `devices`, `doctor`를 실행합니다. 로컬 순정 `fastboot devices`와 장치 인식을 비교합니다. Google 및 가능하면 OEM 드라이버에서 부트로더와 fastbootd 둘 다 확인합니다. |
| 읽기 전용 명령 | 각 클라이언트에서 `getvar product/all/serialno/current-slot/is-userspace/max-download-size`를 실행하고, 같은 모드의 로컬 USB 결과와 비교합니다. 제공하지 않는 변수는 기기 FAIL이 그대로 전달되어야 합니다. |
| ADB 공존 | ADB 원격 목록을 조회하고 확인된 시리얼을 `adb reboot bootloader`로 전환합니다. 다른 Android OS 기기의 ADB 작업이 유지되는지 확인합니다. |
| 부트 모드 왕복 | 부트로더 → fastbootd → 부트로더 → OS 순서로 전환합니다. PnP 인스턴스/시리얼/위치와 로그를 저장하고 포트 매핑이 일정한지 확인합니다. |
| 분리 및 절전 | 유휴에서 USB 분리와 재삽입, Windows Sleep/Resume 후 재접속. 동일한 USB 위치에서 복구하고, 모호한 다른 기기가 포트에 붙지 않는지 확인합니다. |
| 동시에 여러 기기 | 두 기기의 `getvar`를 동시에 실행합니다. 동일 기기를 두 포트에 매핑했을 때 한 세션만 붙고, 다른 기기는 정상 동작해야 합니다. |
| 승인 후 실제 Flash | 대상·파티션·이미지·복구 절차를 먼저 명시하고 사용자 승인을 받습니다. 테스트 기기에서 일반 및 sparse 이미지를 각각 시도합니다. 허용되는 경우 읽기 결과의 해시를 원본/확장 이미지와 비교합니다. |
| 승인 후 네트워크/USB 중단 | 복구 가능한 테스트 기기에서 실제 전송 중 TCP와 USB를 따로 끊습니다. 재시도나 성공 위조가 없고 오류 로그 및 격리가 생기는지 확인합니다. 기기 화면과 실제 결과는 별도로 관찰합니다. |
| 잠금 기기 | 읽기 전용 명령을 실행해 통신 여부를 확인합니다. 명시적으로 승인된 잠금 정책 시험에서는 디바이스가 반환한 거부를 기록합니다. |
| 성능 | 한 기기와 두 기기 동시 전송에서 RTT, USB·TCP·종단처리량, PerfMon CPU/Working Set, PnP 분리 후 재연결 시간을 기록합니다. 1 MiB, 100 MiB, 1 GiB와 기기 한도 내 분할 전송을 구분합니다. |

실제 기기에 대한 Flash, Erase, Unlock은 명시적으로 승인된 시험에만 포함합니다.
