# 문제 해결

| 증상 | 점검 |
| --- | --- |
| `devices`에 기기가 표시되지 않음 | 실제 부트로더 또는 fastbootd 화면인지 확인합니다. 데이터 전송 가능 케이블, 장치 관리자, 해당 모드의 드라이버를 확인합니다. USB 오류로 드라이버가 열리지 않는 장치는 Windows UI에서도 확인합니다. |
| `path=unavailable` 또는 `access=failed` | WinUSB 서비스와 디바이스 인터페이스 GUID를 확인합니다. 로컬 fastboot 및 다른 프록시의 핸들을 닫습니다. 같은 사용자에서 기존 `fastboot devices`와 프록시 `doctor` 결과를 각각 비교하세요. |
| `bind` 오류 | 다른 ADB/Emulator 작업, 프록시 또는 사용 중인 포트를 확인합니다. Windows가 기존 연결을 정리하는 동안 같은 포트가 일시적으로 점유될 수 있습니다. |
| 순정 CLI가 기기를 기다림 | TCP 주소, 포트, Allowlist, 방화벽, Mock에서의 loopback 사용, 매핑된 USB 인벤토리를 확인합니다. 기기가 없거나 사용 중이면 핸드셰이크가 성립하지 않습니다. |
| 재부팅 후 연결 대기 | Windows에서 새 모드가 잡히는지 확인합니다. 시리얼 변경 시 물리 위치와 두 시리얼을 확인하고 별칭을 추가합니다. 기기가 OS로 부팅되면 그 포트는 다시 Fastboot 모드에 들어올 때 온라인이 됩니다. |
| `command outcome unknown` | 명령을 바로 재시도하지 마세요. 기기 화면이나 상태를 확인하고 부트로더를 물리적으로 다시 재부팅하여 DATA 상태를 초기화합니다. 서버에 분리 및 재연결 로그가 나온 뒤 `getvar product`로 재확인합니다. 프로세스 강제 종료 또는 호스트 재시작 후에도 기기를 먼저 초기화해야 합니다. |
| USB 분리 확인 시간 초과 | 케이블과 실제 모드 상태를 확인합니다. `boot` 등 기기별 동작도 USB 분리가 확인돼야 매핑이 자동 복구됩니다. |
| USB 데이터 오류 | DEBUG로 명령과 오류 코드를 확인하고 직접 연결한 케이블에서 재현합니다. `usb_timeout_ms`는 개별 Bulk I/O에 적용됩니다. |

`doctor`는 기기에 Fastboot 명령을 보내지 않습니다. 드라이버와 핸들 접근만 검사합니다. `doctor`의 포트 검사와 USB 접근 검사는 각각 그 자원이 비어 있을 때 성공합니다.
