# 제약사항과 후속 검증

- Windows 10/11에서 실제 Google/OEM 드라이버와 USB 기기의 조합은 실기기 테스트가 필요합니다. Windows Installer, 서비스, ARM64, GUI, UDP 서버는 제공 범위에서 제외했습니다.
- 인벤토리는 `ff/42/03` USB 호환 ID를 게시하는 PnP 장치를 대상으로 합니다. 사용자 정의 연관 인터페이스, 비 WinUSB OEM 드라이버 또는 비표준 Bulk 응답 경계를 가진 기기는 호환되지 않을 수 있습니다.
- 모드별 시리얼이 바뀌면 운영자가 동일 USB 위치의 별칭을 지정해야 합니다. 시리얼과 위치를 동시에 바꾸거나 시리얼이 없는 기기를 재삽입한 경우 자동으로 다른 후보에 연결하지 않습니다. USB 위치가 제공되지 않는 장치는 Windows의 고유 시리얼에 의존합니다. 복제한 시리얼과 물리 포트를 바꾸지 않은 교체를 장치 암호 식별 없이 구별할 수는 없습니다.
- 정적 매핑만 제공합니다. 알려지지 않은 OEM DATA 방향과 DATA 크기 불일치는 격리 처리합니다. 표준 단일 DATA 크기 및 순정 클라이언트의 fetch 크기 한도가 적용됩니다.
- 격리 상태는 실행 중인 프록시 프로세스에서 관리합니다. 호스트 재시작, 강제 종료, 케이블만 뽑았다가 다시 연결한 경우 실제 기기의 잔여 DATA 상태가 초기화되었는지 운영자가 확인해야 합니다. 불확실하면 기기의 부트로더를 물리적으로 다시 시작해야 합니다.
- 공식 TCP 클라이언트는 서버가 오프라인일 때 계속 재접속할 수 있습니다. 종료하려면 클라이언트를 중단합니다. 복합 명령에서 `-s tcp:...`로 같은 매핑을 지정해야 안전합니다.
- 알려진 재부팅 뒤 연결을 다시 여는 동작은 순정 클라이언트에서 확인했습니다. 별도 OEM 재부팅, 무응답 부트로더와 절전 중 드라이버 전이는 하드웨어별로 확인이 필요합니다.
- 서버의 Listen 주소 및 Allowlist는 숫자 IPv4만 지원합니다. 기본 로그 파일 로테이션과 서비스 자동 시작은 지원하지 않습니다.
